Overview:

RunWay is a production-grade fashion e-commerce platform built during Harsh's internship at Cognizant.

The system was designed using microservices architecture where each service owned its own database and business logic.

The project simulated how large-scale enterprise applications are built and deployed in real organizations.

Microservices:

1. Auth Service
2. Catalog Service
3. Order Service
4. Payment Service
5. Engagement Service
6. API Gateway

Service Communication:

The services communicated through:

* Eureka Service Discovery
* OpenFeign Clients

Each service maintained an independent MySQL database.

Biggest Challenge:

Distributed Transactions.

Problem:

An order operation involved:

1. Creating an order
2. Updating inventory
3. Processing payment

These operations occurred across multiple databases.

Traditional database transactions could not be used because each microservice owned its own database.

Solution:

Saga Orchestration Pattern.

Implementation:

The Order Service acted as the central orchestrator.

Workflow:

Step 1:
Order Service creates order.

Step 2:
Catalog Service reserves inventory.

Step 3:
Payment Service processes payment.

Success:
Order confirmed.

Failure:
Compensation steps executed automatically.

Examples:

Inventory reserved but payment failed:
→ Inventory restored.

Order created but inventory unavailable:
→ Order cancelled.
